# Security

## What this is

CommonGround is a demo, not a public service. Anyone can sign in as one of 7 mock personas with no password. The security work protects the integrity of designs and votes and keeps the API answering, and it does not prove who a person is.

## Threat model

Each proof is a test in the named file with that exact name. Every test below passed on 2026-10-03, except the Postgres outage test, which CI skips (see the last section). Paths are relative to the repo root. The route matrix and fuzz names are built from `apps/api/openapi.json` and `apps/api/test/security/matrix-table.ts`, so they appear in the verbose test output, not as literals in the file.

## What is not protected

Sign-in is a mock. Anyone can pick any of the 7 personas, including a resident persona already used by someone else, so a vote proves a session and not a person. One person can cast up to 7 votes per design by signing in as each persona.

No residency check exists. The postal area and age band in a self report are what the resident typed.

Caches are per function instance. The leaderboard is held for up to 5 s on each instance. The rate limiter keeps its buckets in memory unless `RATE_LIMIT_STORE=postgres`, and the Postgres store has not run against Supabase.

No audit log exists. Staff actions, such as publishing a project or changing its status, leave no record of who did them.

No CSRF token or `Origin` check exists. The current routes rely on 3 things instead:

- The session cookie is `SameSite=Lax` with an explicit attribute, so browsers do not send it on a cross-site `POST`, `PUT` or `PATCH`. The test is `packages/auth/src/ports/__contracts__/auth-provider.contract.ts` `marks the cookie HttpOnly with a path and SameSite`.
- Every route with a body takes JSON only. A cross-site HTML form can send only form or text bodies. The route validators accept only `application/json`, and a text body gets a 4xx (`apps/api/test/security/input-hygiene.test.ts` `answers 4xx for a body sent as plain text`).
- All 22 `GET` operations in `apps/api/openapi.json` are reads.

This leaves a gap. `POST /designs/{id}/submit`, `POST /designs/{id}/version` and `POST /auth/logout` take no body, so `SameSite=Lax` alone stops a forged request to them. A page on the same site, such as another subdomain of a custom domain, can send the cookie. The `*.vercel.app` names are on the Public Suffix List, so each one is its own site today. Moving to a shared domain needs an `Origin` check on writes.

A request that times out does not cancel its query. A vote can be saved after the client got a 503. A submit can also commit after a 503, and the retry then answers that the design was already submitted.

Sign-out ends the session only on the instance that took the request. That list is kept in memory. A copied cookie still works on another instance until it runs out, up to 7 days later. Sign-out does clear the drafts saved on this device and its offline copy of the editor. The next person on a shared device does not see them.

The fatal handler logs the whole stack of an uncaught error. A 500 logs only the error's name, the first line of its message and its code, so a driver error does not log its query parameters (`apps/api/src/app.test.ts` `logs a 500 through the Logger port with no query parameters`). No test checks that a stack or a driver message holds no secret. The metrics worker's own failure text is not logged, so a crash leaves no cause in the logs.

gitleaks is not installed on the laptop that ran these checks, so preflight skipped the local secret scan. CI installs a pinned copy.

The Postgres outage test runs only when `PARKSHAPE_TEST_DATABASE_URL` is set and `initdb` and `pg_ctl` are on the path. CI has neither, so the test is skipped there. It passed twice by hand on 2026-10-03 against Postgres 16.15.

Two access rules are open decisions for the project lead. Staff get 404 on residents' drafts, the same as another resident. The baseline design is for signed-in users only, and guests get 401 or 404.
